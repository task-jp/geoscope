🚧 Alpha リリース

❓ ヘルプ

機能リファレンス + 経験則。基本操作を知りたい方は先に 🔰 はじめてガイド をどうぞ。

🛠️ もっと使いこなす

機能が多いので、目的別に詳しく:

🗺️ マップ操作

  • 3 レイヤー: 🩻 赤色立体地図 / 🗾 航空写真 / 🗺️ ベースマップ。各レイヤーは ON/OFF + 透過度スライダ
  • 立体化スライダ: 標高の誇張倍率 (0〜2)。地形のうねりを際立たせる
  • ヘッダの quick toggle: 🩻🗾🗺️⛰️ アイコンで素早く切替
  • 3D 視点: 右クリックドラッグで回転・傾き、Shift+ドラッグで pitch
  • URL の永続化: 開いている場所が /@z/lat/lon/bearing/pitch の URL に随時反映。シェア可能

🏷️ ラベルとアノテーション

  • ⭕❌❓ 投票: 「合ってる」「違う」「保留」を 1 アノテーションに 1 つ。AI 学習のラベルになる (⭕ が正例、❌ が負例)
  • カスタムラベル + 絵文字: ヘッダの 🏷️ ボタンでラベルを追加・編集 (例: 「⭐確定」「📍 現地確認済み」)
  • 選択 → 詳細パネル: 1 件選ぶと右下にメモ・座標・ラベル一覧が出る
  • system ラベル: scan (探索結果) と import (インポート) は削除できない (孤立アノテーション防止)

🔍 フィルタ (複数セット + 空間結合)

サイドバーの「フィルタ」で複雑な条件絞り込みが可能:

  • 1 セット内: ラベル有無 + 投票 + 都道府県 + 名前 (部分一致/未設定) を AND 結合
  • セット間: AND / OR / disjoint (空間的に重ならない)。ST_Intersects で PostGIS が処理
  • 件数制限: 各セットに上限を設定可能
  • 「適用」ボタンを押すまで API は呼ばない (条件を組み立てる時のレンダー負荷ゼロ)
💡 例: 「⭐確定 ラベル」かつ「奈良県」のものから 100 件選ぶ → これを ⭕ で再学習させて精度を上げる、という運用が王道。

🖼️ ギャラリーモード

  • 右上の 🖼 ボタンで切替。フィルタした検出結果を 画像グリッド で一括レビュー
  • 背景レイヤー (基本地図 / 航空写真 / 赤色立体地図) を切り替えながら判定可能
  • 👍 / 👎 で 1 件ずつ承認/却下、一括選択して投票やラベル付与もできる
  • サムネは CDN タイル + CSS クロップで生成 (バックエンド負荷 0)

📥 インポート / 📤 エクスポート

  • GeoJSON インポート: Point または Polygon。Point は緯度経度から bbox を自動推定 (タイル内分数位置)
  • CSV インポート: lat,lon ベース。1 列で名前 (label) を持てる
  • GeoJSON エクスポート: 2 形式 (bbox / point)。QGIS や Google My Maps で開ける
  • uMap 用 GeoJSON: 名前 + ラベル + GeoScope へのリンク付き、uMap にそのまま貼れる
  • Google Sheets CSV: サムネ URL 付き、Sheets で =IMAGE() でプレビューできる
  • インポートで作られたアノテーションには「📤 YYYY/MM/DD HH:MM:SS インポート」ラベルが自動付与 (後で一括削除可能)

⚙️ 探索モードの選び方

アカウント設定 → 🚀 探索GPU で 3 つから選択:

モード GPU 1 回 特徴
🐌 節約Community 4090500〜700円 最安、ただし在庫切れ時は永久リトライで時間かかる
⚖️ 標準Secure 4090約 800円 在庫安定、ほぼ即起動。default 推奨
⚡ 急ぎSecure + H100 等800〜1500円 最速、短納期や急ぎの実証で

💻 ローカル GPU セットアップ詳細

RTX 4090 などを持っているなら、自宅マシンで worker を動かせます (運用コスト 0 円、電気代のみ):

  1. アカウント設定 → 🚀 探索GPU → 💻 ローカル GPU 選択
  2. (任意) ☑️ 自動再起動 / ☑️ DEM キャッシュ保存 を選ぶ
  3. 表示された docker run コマンドをコピー → 自宅 PC で実行
  4. 必要なホスト側ソフト: NVIDIA GPU ドライバ / Docker / nvidia-container-toolkit
  5. ブラウザの「探索」ボタンを押すと、自宅 worker が polling で claim → 処理
💡 複数台に同じ WORKER_API_KEY を設定すると、スキャンのタイルが分担されて並列処理されます (学習自体は 1 台、その後のスキャン段階で並列化)。フェイルオーバーにもなります。

📍 名前付与 (Google Places)

  • アカウント設定 → ⚙️ その他 → Google API Key を入れる (任意)
  • 検出結果のフィルタを適用 → ギャラリーで 📍 Google ボタン
  • 各検出地点から半径 100m 以内の最寄り Place 名 (神社・古墳・遺跡等) を距離順に取得し、ラベルとして付与
  • 行政区域 (○○市 等) は除外
  • キーワード絞り込み (経験則): 古墳系を対象にしているなら「墳」、城址/城跡を対象にしているなら「城」をキーワードに入れると、関係ない Place 名で汚染されず精度が高まる
  • Google API はキー保有者に課金。Places API の $200/月の無料枠 がある

🛰️ Mapbox 衛星画像 (オプション)

  • デフォルトは 国土地理院の航空写真 (無料・無制限)
  • より高解像度な衛星画像が必要なら、自分の Mapbox トークン を入れることで Mapbox Satellite に切替
  • Mapbox はトークン保有者に課金 (月 50,000 リクエストまで無料)

🔄 中断と再開

  • 探索ジョブは backend が管理。ブラウザ閉じても処理は進む
  • worker や Pod がクラッシュしても、最後の保存ポイント (10,000 タイルごと) から自動再開
  • RunPod 側で Pod を手動停止した場合は、次回「探索」を押せば新 Pod が起動して続きから

🧹 結果の整理ワークフロー

  1. 探索完了 → scan の一時ラベル付きアノテーションが多数追加される
  2. ギャラリーモード 🖼 で 1 件ずつ 👍/👎 投票
  3. フィルタで annotation_vote=yes + その scan の一時ラベルを絞り込む
  4. 本物に 永続ラベル (例: 「前方後円墳」) を一括追加付与
  5. scan の一時ラベルを一括削除 → 本体は永続ラベル付きで残る
  6. 再学習ボタン (🎯 再スコア) または 再探索で精度を上げる、これを繰り返す

💡 ベストプラクティス (経験則)

AI の精度を上げるためのノウハウ。これに従うとモデルがすぐに賢くなります。

⭕❌❓ の使い分け

  • ⭕ (正例): 確実に教師データになるもの。「これは間違いなく対象 (例: 前方後円墳)」と断言できる地物だけに付ける
  • ❌ (負例): 明らかに間違いなもの。「これは似てるけど絶対違う」という典型例を集めると、AI が混同しなくなる
  • ❓ (保留): 教師データにしないもの。既知の偽陽性、判断が割れる微妙なもの、要再調査のもの。学習からは無視される
💡 「悩むものを ⭕ に入れない」のが鉄則。確度の低い ⭕ を増やすと AI の判断軸がぼやけます。

ラベルは 1 つ (以上) を永続運用 — 探索ごとに作らない

よくある誤解: 「探索ごとに新しいラベル」ではありません。 正しい運用は 「前方後円墳」など 1 つの永続ラベル を用意し、 何回も探索を回しながら、その都度の検出結果の中から見つかった本物を そのラベルに追加していく、というやり方です。⭕❌ を調整しながら何サイクルも回して 「前方後円墳」ラベルを育てていきます。

サイクル全体像:

  1. 「前方後円墳」というラベルを 1 つ作る (絵文字: ⛩️ 等)
  2. 探索を実行 → 検出結果には scan の一時ラベル (例: 2026/05/15 12:00 全国) が付く
  3. ギャラリーモードで結果をレビューし、本物 (⭕) に「前方後円墳」ラベルを追加付与
  4. 明らかに違うものには ❌、微妙なものには ❓
  5. 整理後、scan の一時ラベルは一括削除して OK (本体は「前方後円墳」ラベルに紐付き済み)
  6. 再学習・再探索 → 前方後円墳ラベル内の ⭕ がさらに増える
  7. 3〜4 サイクル繰り返すと精度が大幅向上 (経験則)

「前方後円墳」ラベル内の ⭕ 割合を管理

永続ラベル (例: 「前方後円墳」) の中の ⭕ 割合 がモデル品質の指標になります:

  • ⭕ 割合 50〜60% が目安
  • 多すぎる (> 60%): 教師過剰 → 同じものしか拾わなくなり、新しいものを見逃す。⭕ を間引くか ❌ を増やす
  • 少なすぎる (< 50%): 教師不足 / 偽陽性多すぎ → ⭕ を増やすか bbox を絞る

始め方: 手動 50〜100 個 → 探索で増やすループ

  1. 最初に手動で 50〜100 個 の既知アノテーションを ⭕ で作成し、永続ラベル (例:「前方後円墳」) を付与
  2. 「探索」実行 → 結果が出る
  3. 結果から本物を選別、⭕ + 「前方後円墳」ラベル追加付与。違うものに ❌、微妙なものに ❓
  4. scan の一時ラベルは整理後にまとめて削除 (永続ラベル付きの本体は残る)
  5. 再学習・再探索を繰り返してラベルを充実させる
🎯 最初の手動 50 個が一番大事。ここで質の高い ⭕ を集めると、その後がぐっと楽になります。

バウンディングボックスは「対象に対して」一貫した囲み方を

  • bbox は 対象の輪郭ギリギリ がベスト。広く取りすぎると周辺の地形まで学習対象になってしまう
  • 大事なのは 「対象物に対する bbox の囲み方」が揃っていること。例えば前方後円墳ならどの大きさのものでも「外周をぴったり、周濠は含めない」など、ルールを統一する
  • (対象物そのもののサイズは大小ばらつくのが当然なので、絶対サイズを揃えるという意味ではない)
  • 定期的に ⭕ の見直しと bbox の調整 を推奨。古い ⭕ で「囲み方の揺れ」が大きいものを直すだけで精度が体感できるほど上がる
💡 「再学習前に古い ⭕ の bbox 囲み方を統一する」を習慣にすると、サイクルが進むほど精度が安定して伸びる。

❓ よくある質問

RunPod 課金が怖いです。安全策は?

RunPod ダッシュボードで「Spending Limit」を月額 $20 などに設定できます。GeoScope 側からは料金を発生させる操作 (Pod 起動) しかしないので、上限を設けておけば暴走しません。

1日中ブラウザを開いておかないとダメ?

不要です。探索ジョブは backend が管理しているので、ブラウザを閉じても進みます。結果は次回ログイン時に表示されます。

他人のプロジェクトは見える?

見えません。プロジェクト・アノテーション・検出結果はすべて作成者本人にのみ表示されます。AI 学習もユーザー単位で完全に独立しています。

アカウントを削除したい

右上のアバター → アカウント設定 → 「アカウント削除」。プロジェクト・アノテーション・検出結果はすべて即時削除されます (復旧不可)。

地図 URL をシェアできる?

/@z/lat/lon/bearing/pitch の URL は誰でも閲覧できます (OG メタタグ付き)。Twitter や Discord に貼ると地図の位置と方角がそのまま再現されます。

探索を早く終わらせたい。複数の GPU を並列で使えない?

現状は 1 ユーザー = 1 GPU で固定です (RunPod 在庫を抑える設計)。早く終わらせたい場合の代替策:

  • 「⚡ 急ぎモード」で H100 等の高性能 GPU を選ぶ → スキャン時間 1/2 程度
  • 自分のローカル GPU と RunPod を 同時に 動かす (両方に同じワーカー API キーを設定するとスキャン段階でタイルが分担される)
  • 探索範囲を都道府県等で絞る → タイル数が全国の数% で済む

「同一ユーザーが複数 RunPod GPU を並列で動かす」設定 UI は今後の検討項目です。
